# Example

**The data in this folder are synthetic.** They imitate a retrieval experiment
on regulatory documents but are random numbers generated by
[`generate_synthetic.py`](generate_synthetic.py), not results of real systems.

| File | Content |
| --- | --- |
| `data/qrels.txt` | 40 queries, 1-5 relevant documents each (grades 1 and 2) and 5 judged non-relevant ones |
| `data/runs/bm25.run` | lexical baseline, one run |
| `data/runs/dense.seed{1,2,3}.run` | dense retriever, one run per random seed |
| `data/runs/hybrid.seed{1,2,3}.run` | score fusion of BM25 and the dense run with the same seed |
| `expected/report.md` | the report produced by the command below |
| `expected/report.png` | the chart |

About a fifth of the queries depend on exact terms: the dense retriever fails on
them and the hybrid recovers through BM25. Look for them in the per-query output.

## Reproduce

From the repository root:

```bash
python examples/generate_synthetic.py
reteval evaluate --qrels examples/data/qrels.txt \
  --run bm25=examples/data/runs/bm25.run \
  --run "dense=examples/data/runs/dense.seed*.run" \
  --run "hybrid=examples/data/runs/hybrid.seed*.run" \
  --metrics ndcg@10 recall@10 mrr@10 map --baseline bm25 \
  --output examples/expected/report.md \
  --per-query out/per_query.csv --plot out/report.png
```

The CI job "Example report in the locked environment" runs exactly these commands
with the versions in [`requirements-lock.txt`](../requirements-lock.txt) and fails if
the data or the report differ from the committed files.
